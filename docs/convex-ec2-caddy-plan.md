# Self-hosted Convex on EC2 behind Caddy

Goal: one t4g (arm64) instance running the Convex compose stack, fronted by a
system-level Caddy that terminates TLS with Route53 DNS-01 certificates.

| Public host              | Local target     | What            |
| ------------------------ | ---------------- | --------------- |
| `site.<domain>`          | `127.0.0.1:3211` | HTTP actions    |
| `api.<domain>`           | `127.0.0.1:3210` | API + WebSocket |
| `dashboard.<domain>`     | `127.0.0.1:6791` | Dashboard       |

Files: the compose stack and Caddyfile are both generated by
`infra/convex-backend.ts` (ports bound to loopback).

## 1. Caddy binary

No Go toolchain needed. The binary is a release asset of
[caddy-linux-arm64](https://github.com/christianstamati/caddy-linux-arm64),
itself the output of the Caddy download API with plugins:

```
https://caddyserver.com/api/download?os=linux&arch=arm64&p=github.com/caddy-dns/route53
```

Same URL with `os=darwin&arch=arm64` for this Mac. `xcaddy build --with
github.com/caddy-dns/route53` is the equivalent if you prefer to build.

## 2. Test on this machine

1. `cp .env.example .env`, set `DOMAIN`, generate `INSTANCE_SECRET`.
2. Point the three names at this machine in `/etc/hosts` (`127.0.0.1 site.<domain> api.<domain> dashboard.<domain>`).
   DNS-01 never needs inbound traffic, so real DNS can stay untouched.
3. Uncomment the staging `acme_ca` line in the Caddyfile for the first run.
4. `docker compose up -d`, then `DOMAIN=<domain> AWS_PROFILE=<profile> sudo -E caddy run --config Caddyfile`
   (sudo because of ports 80/443; `-E` keeps the AWS env).
5. `curl https://api.<domain>/version`, open the dashboard, paste the admin key from
   `docker compose exec backend ./generate_admin_key.sh`.
6. Switch back to production ACME, delete `~/.local/share/caddy` so staging certs are dropped.

## 3. AWS pieces (SST, `infra/convex.ts`)

- **IAM role + instance profile**: Route53 `ListHostedZones`, `ListHostedZonesByName`,
  `GetChange`, and `ChangeResourceRecordSets` scoped to the hosted zone; `ssm:GetParameter`
  for the secrets below.
- **SSM parameters** (SecureString): `/mnlth/convex/instance-name`, `/mnlth/convex/instance-secret`.
  Stable values are what keep admin keys valid across reboots.
- **Security group**: inbound 80 and 443 only. SSH via SSM Session Manager, no port 22.
- **Elastic IP** and three Route53 A records (or one wildcard) pointing at it.
- **Instance**: t4g.small or larger, Amazon Linux 2023 arm64, root volume 30 GB gp3.
  Data lives in the `data` docker volume on that disk; snapshot it or move it to a
  separate EBS volume before this is production.

## 4. userData script (runs once at first boot)

1. `dnf install -y docker`, `systemctl enable --now docker`.
2. Install the compose plugin: download `docker-compose-linux-aarch64` from the
   docker/compose GitHub release into `/usr/local/lib/docker/cli-plugins/docker-compose`.
3. Download Caddy from the URL in section 1 to `/usr/bin/caddy`, `chmod +x`, create the
   `caddy` user, install the upstream systemd unit, add `Environment=DOMAIN=<domain>` and
   `Environment=AWS_REGION=<region>` to it.
4. Write `/etc/caddy/Caddyfile` (the file in this repo, embedded via heredoc or
   fetched from S3).
5. Write `/opt/convex/docker-compose.yml` and `/opt/convex/.env`. The `.env` origins come
   from `DOMAIN`; `INSTANCE_NAME` and `INSTANCE_SECRET` are read from SSM with the AWS CLI.
6. `docker compose -f /opt/convex/docker-compose.yml up -d`.
7. `systemctl enable --now caddy`.

Order matters only for step 6 before 7 so the proxy targets exist when Caddy starts.
Compose services carry `restart: unless-stopped`, so a reboot recovers without userData.

## 5. After it is up

- Generate the admin key on the instance:
  `docker compose -f /opt/convex/docker-compose.yml exec backend ./generate_admin_key.sh`.
- `CONVEX_SELF_HOSTED_URL=https://api.<domain>` plus the key for `npx convex deploy`.
- Later hardening: `basic_auth` or IP allowlist on `dashboard.<domain>`, S3 buckets for
  file storage, Postgres instead of the embedded SQLite, EBS snapshots.
